# Pinna.design — original design direction

## Concept: Signal / Structure / Surface

Pinna is treated as a visual practice that receives complexity and turns it into an intelligible system.

The identity is expressed through three ideas:

- **Signal** — the message must be perceived quickly.
- **Structure** — the underlying grid, type hierarchy and information architecture are exact.
- **Surface** — paper, print, image and material introduce texture and character.

The original Pinna mark is a vertical spine with a family of expanding lines. It can suggest a receiver, a leaf structure, a fin or a typographic construction without becoming one literal symbol.

## Visual character

- Off-white paper and near-black ink.
- Colour comes from project artwork.
- One variable grotesk carries display and body copy.
- System monospace is used sparingly for years, counts and technical labels.
- Geometry is predominantly square.
- Project media is large and borderless.
- Negative space is active and carefully distributed.
- There are no decorative gradients, glass effects, soft SaaS cards or default component-library patterns.

## Typographic position

Typography is the permanent interface identity. Project artwork changes; the typographic structure does not.

Use a clear hierarchy:

- compact practice labels
- oversized but readable display statements
- concise project titles
- disciplined year and category metadata
- body copy with a generous measure and line-height

Display text may be tight. Body text may never be tight.

## Interaction character

- Native scrolling.
- No smooth-scroll library.
- One subtle pointer response in the Pinna line field.
- Masked image reveals that never alter layout geometry.
- Project-cover continuity through a persistent root-layout overlay that survives App Router navigation.
- Immediate, clean navigation when the enhancement is unavailable or reduced motion is requested.
- Mobile removes pointer-dependent and complex scroll behaviour.
- Reduced-motion mode is fully designed.

## Motion hierarchy

Motion belongs to four functions only:

1. reveal hierarchy
2. communicate a control state
3. preserve continuity during project navigation
4. add restrained ambient life to the Pinna field

Anything outside those four functions is removed.

## Why this is high-end

The premium result comes from authored decisions rather than effect count:

- exact type
- considered line breaks
- confident media scale
- consistent information
- stable loading
- clean routing
- restrained motion
- strong keyboard and mobile behaviour
- no accidental or generic component styling
